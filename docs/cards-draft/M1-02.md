It contains LICENSE, VENDORED.txt, ares/ares/ (framework: nodes, Platform, scheduler), ares/component/ (CPU cores such as wdc65816 and spc700), ares/sfc/ (Super Famicom), nall/ (support library) and libco/ (coroutines). Interface. Keep it exactly like this; the SDL3 frontend card builds on it:
```cpp
// src/core/core.hpp
#pragma once
#include <cstdint>
#include <string>
#include <vector>
namespace snes2dhd {
struct Frame {
  std::vector<std::uint32_t> pixels;  // width*height, row-major, no row padding, XRGB8888
  std::uint32_t width = 0, height = 0;
};
// Loads a ROM file and powers on the SNES. Returns an error message, or "" on success.
std::string load(const std::string& rom_path);
// Runs emulation until ares delivers the next video frame, and returns it.
const Frame& run_frame();
void unload();
}
```

src/core/core.cpp:
- Implement ares's Platform interface (external/ares/ares/ares/platform.hpp), set the global ares::platform, and load the Super Famicom system (entry point in external/ares/ares/sfc/). Upstream's desktop-ui/emulator/super-famicom.cpp shows the order: load the system, connect the cartridge slot, power on. These names are from memory of ares; use whatever the vendored headers actually say.
- pak() for the cartridge: an in-memory pak that holds the ROM bytes as program.rom, plus whatever board/manifest info external/ares/ares/sfc/cartridge/ reads. Use a plain LoROM board with no coprocessor and no SRAM: ROM mapped at banks 00-7d,80-ff:8000-ffff, mask 0x8000. Mark it `// shortcut: LoROM only, no coprocessors; upgrade when a test ROM needs HiROM or a coprocessor`.
- video(): copy the screen into Frame (drop any pitch padding) and set a "frame ready" flag. run_frame() keeps calling the system's run function until the flag is set. If ares's pixel format is not XRGB8888, convert here.
- audio()/input(): no audio output and no buttons pressed. Drain and discard samples if the stream API requires it.
- Output must be deterministic. If two runs give different hashes, find ares's power-on randomisation (search "random" in external/ares/ares/ares/ and external/ares/ares/sfc/) and set a fixed seed from our code.

src/headless/main.cpp: usage `snes2dhd-headless --frames N <rom>`, with N ≥ 1.
- Bad command line → print usage to stderr, exit 2.
- Load error → print the error to stderr, exit 1.
- Otherwise run N frames and print exactly `frame <N> <W>x<H> sha256=<lowercase hex>`. The hash is the SHA-256 of the last frame's pixel bytes (u32 little-endian, row-major), computed with nall's SHA-256 (under external/ares/nall/). Do not write your own hash.

tests/headless/make_min_rom.py <out path>: writes our own 32 KiB LoROM test program. It contains no game data. Never commit its output; always write it under build/ or a temp dir.
- 32768 bytes, filled with 0xFF.
- At offset 0, the code: 78 18 FB A9 80 8D 00 21 9C 21 21 A9 1F 8D 22 21 9C 22 21 A9 0F 8D 00 21 80 FE
  (SEI; CLC; XCE; force blank; CGRAM colour 0 = red; screen on at full brightness; loop forever.)
- Header at 0x7FC0: a 21-byte title "SNES2DHD MIN TEST" padded with spaces. Then 0x7FD5=0x20 (LoROM), 0x7FD6=0x00, 0x7FD7=0x05 (32 KiB), 0x7FD8=0x00, 0x7FD9=0x01, 0x7FDA=0x00, 0x7FDB=0x00.
- Every 16-bit word from 0x7FE0 to 0x7FFE = 0x8000, little-endian (all vectors point at the code).
- Checksum: write 0xFFFF at 0x7FDC and 0x0000 at 0x7FDE. Sum all bytes & 0xFFFF to get c. Then write c at 0x7FDE and c ^ 0xFFFF at 0x7FDC (little-endian).
- The expected picture is solid red.
